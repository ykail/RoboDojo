# Task-Specific VQA Specification: RoboDojo `make_kong`

This specification extends `01_vqa_data_format.md`.  It covers the synthetic,
ego-view-only VQA sidecar produced by `generate_make_kong_vqa.py`.

## Scenes and overlay

Each scene contains the 12 robot-side tiles, one matching reference discard
tile, and exactly one of the eight fallen-state bitmasks for the three matching
tiles. The opponent reference discard is knocked down toward the robot with
its face visible before the robot-side state is rendered; its category is the
visual basis for selecting the three matching tiles. The final ego RGB image has uniform numeric badges and leader lines
for robot-side tiles 1 through 12.  The badge-to-instance mapping is stored in
`overlay_mark_to_instance_json`; badges never encode the tile class or fallen
state.

The generator retains a record only when the reference tile, queried tile, and
their segmentation masks are visible in `cam_head`.  Wrist images, hidden
layout state, and custom list-valued answers are not model inputs or targets.

## Question families

### `matching_tile_needs_to_be_pushed`

Prompt:

```text
Based on the face-up reference tile, does the tile marked {mark} still need to be knocked down? Answer yes or no.
```

- Answer type: `boolean`
- Per reference group, the collector queries only the leftmost and rightmost
  tiles of its three matching robot-side tiles; the centre tile remains visual
  context and is never queried.
- `yes` means the queried matching tile is still upright; `no` means it has
  already been knocked down.
- All eight bitmasks are generated by default, giving exactly balanced `yes`
  and `no` labels for each queried outer position.

## Output invariants

- `target_view = "ego"` is implicit for this boolean family; each record
  references one 640×480 `cam_head` PNG.
- `world_state_valid` and `image_answerable` must both be true for accepted
  rows.  Invalid segmentation mappings, invisible tiles, or overlay placement
  failures appear only in `rejected.parquet`.
- `gt_source = "simulated_tile_identity_and_pose"` and
  `annotation_version = "robodojo_vqa_v1"`.
- The old `<already_pushed>...</already_pushed><need_push>...</need_push>`
  serialization is not part of this dataset.
